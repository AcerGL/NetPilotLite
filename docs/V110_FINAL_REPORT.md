## 2. 残影根因及修复

旧版逐控件 `MoveWindow(..., TRUE)` 在布局中途触发重绘；父窗口未裁剪子控件；设置页移动已绘制像素和部分出界控件，背景、文字及子控件刷新不能保持一致。每次绘制还重复创建位图、缩放大图。

现在统一缓存完整内容层，再截取视口，静态文字与背景采用相同滚动坐标；批量定位控件后统一重绘。设置页有独立裁剪视口，标题和导航固定。尺寸、主题、内容改变才重建缓存。图片解码在后台；原图不透明时使用 HALFTONE 缩放。详细代码依据与试验过程见 `V110_STAGE_A.md`。

## 7. Stage B 技术结论

Windows 的应用身份识别、连接过滤、路由选择、透明重定向是不同能力。`IP_UNICAST_IF` / `IPV6_UNICAST_IF` 用于应用自身 socket；普通路由条目不按 PID，不能用修改全局 Metric 代替任意应用分流。WFP 可表达部分过滤约束，透明重定向涉及更复杂的 callout/代理路径，且不能据此承诺所有协议、代理及 VPN 的物理出口隔离。

系统端点表可以观察 PID 和地址，`GetBestRoute2` 只能提供查询当下路由估计。源地址属于某张网卡不等于数据包最终从该硬件发出。应用连接本地代理后，远端连接可能属于代理进程；UDP 表不提供每个远端流，DNS/DoH 及 QUIC 还需额外验证。十个技术问题、微软文档引用、Clash/VPN 模式矩阵和恢复策略详见 `ROUTING_FEASIBILITY.md`。

## 8. 已实现与未实现

已实现：当前网络隔离区的 TCP/UDP IPv4/IPv6 端点读取、有限权限进程路径查询、物理身份映射、IPv6 scope 和重复地址处理、回环与虚拟接口标记、路由估计；最多 32 条可保存的观察规则，默认关闭，支持目标选择、启停观察、删除、清空和诊断比较。表格最多 1024 行，超限明确标注截断。连接记录不写入持久日志。

**未实现/未启用：任意 EXE 强制使用某网卡、失败时阻断回落、WFP 保护规则、透明代理重定向、物理出口证明。** 界面不显示“分流成功”；规则的“启用”明确指观察。没有默认启用示例规则，没有安装过滤器、服务、驱动或计划任务。

B1 可行性、B2 只读模块、B3 映射限制验证、B4 模拟规则已完成。B5 的 Clash System Proxy/TUN、VPN full/split tunnel 全模式实测未完成；B6–B8 控制与隔离验收暂未完成。用户确认没有可用 Windows 隔离环境，因此按允许先发布只读模块的范围交付，没有在正在使用的电脑上试装网络阻断策略。
